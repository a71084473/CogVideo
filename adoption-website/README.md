# 安心託付・共同陪伴|中途之家認養網站

一個以「**提高適合且能長期穩定的認養率**」為目標的認養服務原型——不是讓人更快帶走動物,而是讓合適的人更安心地承擔。北極星指標為「認養後 90 天穩定率」,搭配主動求助率、準備完成率、失聯率與退養率。

## 快速開始

```bash
npm install
npm run dev      # 開發模式
npm run build    # 產出 dist/
npm run preview  # 預覽建置結果
```

技術棧:React 19 + TypeScript + Vite + Tailwind CSS v4 + React Router(HashRouter,便於靜態部署)。收藏、測驗續填、準備清單、預約、求助與幸福回報皆以 localStorage 模擬,**不儲存身分證、地址或敏感醫療資料**。

## 一、資訊架構摘要

```
首頁
├─ 尋找適合的夥伴 /animals(生活適配篩選:新手友善、獨處時間、活動量、
│   親人程度、多寵/兒童、特殊醫療、預算、空間、地區、單獨/成對)
│   └─ 動物詳情 /animals/:id(故事+真實生活+健康+適合/不適合+中途支持)
├─ 生活適配測驗 /quiz(12 題、一步一題、可續填)
│   └─ 測驗結果 /quiz/result(三種狀態:已適合媒合/完成準備後媒合/先用其他方式參與)
├─ 認養流程與共同準備 /process(五步驟,每步含目的/時間/資料/回饋/個資使用)
├─ 會員中心 /dashboard(測驗結果、收藏、預約、準備清單、90 天節點、隱私、求助入口)
├─ 認養後 90 天支持 /support-90(3/7/30/60/90 天時間軸)
├─ 危機求助 /crisis(七種情境+問題分流表單,強調不得私下轉送或棄養)
├─ 幸福回報 /happiness(輕量回報+公開設定+成長時間軸)
├─ 助養、捐款與志工 /get-involved(8 種參與方式,含時間/技能/責任/影響)
└─ 關於我們與透明資訊 /trust(認養標準與原因、隱私、捐款流向、合作揭露)
```

行動版底部導覽:首頁、找夥伴、適配測驗、進度、求助。

## 二、核心使用者流程

1. **主流程**:首頁 →「開始生活適配測驗」→ 12 題(每題附「為什麼要問」)→ 三態結果 → 推薦 1–3 隻動物 → 動物詳情(故事+真實揭露)→「看看我們是否適合彼此」→ 4 題快速適配確認 → 預約實體互動/線上諮詢 → 會員中心追蹤準備清單 → 責任交接 → 90 天支持 → 幸福回報。
2. **可培育新手型**:首頁「你不需要一開始什麼都會」→ 新手友善篩選 → 客製準備清單(含新手課程)→ 90 天陪伴。
3. **共感陪伴型**:動物故事 →「一起生活的真實樣貌」與「可能不適合」並列 → 期待校準題(「三個月不主動靠近,你願意等嗎?」)→ 鼓勵實際互動,不用倒數/稀缺話術。
4. **條件不穩定型**:情境規劃題(搬家/出差/失業/醫療/家庭)→ 缺口轉為準備清單而非否定 → 結果 B「還有幾項準備完成後,就能更安心進入媒合」;結果 C 導向志工/助養/課程,結果保留可隨時回來。
5. **求助流程**:任何頁面(底部導覽/會員中心/90 天頁)→ 危機求助 → 七分類+緊急程度 → 非責備回應;「真的無法繼續」明確要求優先聯絡原中途。

## 三、UX 決策說明

- **第一 CTA 是「開始生活適配測驗」而非「立即認養」**:轉換目標是適配而非速度;動物卡 CTA 為「了解牠的真實生活」。
- **三態結果、絕不出現「不合格/淘汰」**:媒合邏輯(`src/lib/match.ts`)把缺口轉成準備項目,只有在經驗、備援、醫療準備同時缺位時才建議先以其他方式參與,且明示結果會保留。
- **不以單一條件判斷**:測驗不問收入數字、不問職業;問的是「突發醫療費你目前的準備」「誰能接手幾天」等具體備援行動。
- **雙向透明**:動物頁同時揭露健康、行為、照護難度、預估支出與「可能不適合」;每個敏感題附「為什麼要問」與資料用途說明。
- **家訪重新命名**為「居家安全確認與改善協助」,並承諾居家照片確認後即刪除。
- **無障礙**:skip link、可見 label、44px 點擊區、radiogroup/fieldset 語意、錯誤訊息緊鄰欄位且不只用顏色、`prefers-reduced-motion`、鍵盤焦點樣式、alt 文字。
- **示意資料誠實標註**:信任數字、捐款流向、時間軸皆標「示意資料」,不假裝真實成果;示意圖角落有「示意圖」浮水印。

## 四、Mock Data

- `src/data/animals.ts`:8 隻動物(麻糬/豆腐/拿鐵/海苔/雪見/榛果/杏子/奧利歐),涵蓋幼貓成對認養、慢熟成貓、慢性病老貓、高活動量犬、警戒犬、三腳貓、熟齡犬等不同照護難度。
- `src/data/quiz.ts`:12 題測驗(動機、期待校準、居住、同住者、獨處時間、出差、經驗、預算、突發醫療、備援、情境規劃、照護接受度)。
- `src/data/preparation.ts`:6 項共同準備(門窗防護、房東同意、第二照顧者、醫療預備金、基本用品、新手課程)。
- `src/types.ts`:Animal、ApplicantProfile、MatchResult、PreparationItem、AdoptionCase、SupportRequest、HappinessUpdate。

## 五、未來串接建議

1. **後端與身分驗證**:以 Supabase/PostgreSQL 取代 localStorage;敏感欄位(聯絡方式、合約)僅存後端並加密,前端只留 token。ApplicantProfile 與 MatchResult 移至伺服器計算,支援「新夥伴符合條件時通知我」。
2. **預約系統**:中途端行事曆(可用 Cal.com 自架)+ 雙向確認與提醒(email/LINE Notify);預約狀態機:已送出→中途確認→已確認→已完成。
3. **訊息中心**:認養案件為單位的對話串(AdoptionCase.messages),支援附件(醫療紀錄);90 天節點自動排程訊息,逾期未回報僅溫和提醒一次。
4. **金流**:捐款/助養接綠界或藍新定期定額;收據與年度徵信自動化,對應透明頁的流向報告。
5. **後台**:中途管理動物資料(上架前檢查表強制填寫「可能不適合」欄位)、案件看板(依五步驟)、求助工單(依緊急程度排序)、黑名單僅內部風險註記、不公開。
6. **正式照片規範**:統一 4:3、不裁頭部、自然居家場景;上傳時強制 alt 文字。
