# 領養意願 UX 體驗測試報告(兩輪迭代)

以四篇中途之家深度訪談為證據基礎,建立五位領養者 persona,對「安心託付 × 共同陪伴」網站進行兩輪測試 → 假設 → 優化的迴圈。

**測試方法**:Playwright 驅動真實瀏覽器(桌機 1280×900 / 行動 390×844),走完各 persona 的實際點擊路徑,擷取他們在每個決策點真正看得到的內容,再依訪談證據逐條檢核。測試腳本在 `ux-test/`,可重跑。

---

## 一、訪談證據萃取

四篇訪談的受訪者分別是:大型協會負責人(8–9 年,專職團隊)、FB 社團管理員兼新設協會發起人(台中)、個人中途(雙北,奶貓幼兒園)。他們描述的**認養人樣態**,是本次 persona 的來源。

### 直接決定「領養意願」的六個發現

| # | 訪談原文(節錄) | 對網站的意涵 |
|---|---|---|
| 1 | 「我po送養文就會把 Google 表單放在裡面,但我發現**大家點進去表單,看到那一堆問題的時候,就不會有人填了**」;另一位:「**問卷一出去人就不見了**」 | 表單長度本身就是最大的流失點。網站的 12 題測驗有同樣風險。 |
| 2 | 「幸福回報…我覺得它有點像**電子腳鐐**…這個或多或少都會讓一些認養的人不舒服,甚至非常明顯的抗拒,但我們沒辦法說抗拒這樣事情的人就是壞人,**他很有可能只是非常在意自己的隱私而已**」 | 追蹤機制若不先解除監視感,會直接勸退在意隱私的人。 |
| 3 | 「**系統來提醒你,不是人來提醒你**」;「我送養 100 隻貓,一個月要回報一次,我哪會記得」 | 自動化提醒同時解決中途的負擔與認養人的壓迫感。 |
| 4 | 「越來越多的人**不喜歡到中途之家去認養貓,他覺得說要被檢查很多東西**」;「認養人跟送養人的對立跟衝突越來越明顯…他們有沒有**被妖魔化**」 | 網站要求中途對認養人透明,卻沒讓認養人理解中途——雙向透明只做了一半。 |
| 5 | 「**同住家人一定要同意**,因為曾經碰過小孩想認養,可是後來父母不同意」;「**他的房東有沒有同意讓他養貓**」 | 卡點常不在認養人身上,而在他說服不了的第三方。 |
| 6 | 「橘白貓是最搶手…**玳瑁真的不太好送**,因為顏色花花的不討喜」;「奶貓潮…量變大了,所以你的貓會變得比較送不出去」 | 送養速度由外型決定,平台若只按適配分排序,久候者依然沉底。 |

### 支撐既有設計的證據(確認方向正確)

- **家訪重新定義**:訪談 4 本人就這樣描述——「我們家訪的目的是**協助你做的防護是不是很安全穩固**…如果他那邊做得不好,我們就請他加強,我們會教他怎麼做」。網站的「居家安全確認與改善協助」命名與這位中途的實務完全一致。
- **不賣慘的動物敘事**:「我並不會試著把牠寫得很可憐…**我會把牠敘述成是一個人**」→ 因共感而來的人「**退養的可能性小很多**」。
- **態度重於條件**:「我問職業的時候我都不會去問收入,因為有些人雖然沒什麼錢但是他很用心」;「**他只要心態上正確就 OK**」。
- **持續支持勝過嚴審**:「**與其讓這一個人把這隻貓退回來**…倒不如我們現在投入時間人力物資,去協助他們一起跨越那個困難」。
- **一次審核不保證未來**:退養案例——「一開始牠就是好好的,然後中間也不知道怎麼樣」,接回來時「全身都是跳蚤…很瘦…皮膚病牠都不知道」。

## 三、第一輪測試:結果與假設

### 通過的項目
測驗 12 題**每一題都有「為什麼要問這題」**(0 題遺漏)、結果頁有「不是人格評分」聲明、動物頁有「可能不適合」與每月支出、成對認養有社會化理由與雙倍成本、危機頁七情境齊備、行動版底部導覽完整、無 JavaScript 錯誤。

### 發現的意願崩落點與假設

| 假設 | 崩落點(persona) | 證據 |
|---|---|---|
| **H1 中途無回饋的長表單會流失** | P1 在第 6–8 題放棄 | 訪談 1、3 直證 |
| **H2 未主動解除監視感 = 默認被監視** | P2 讀 90 天頁後意願下降 | 90 天頁**沒有**「系統提醒不是人催」、**沒有**說明誰看得到回報 |
| **H3 否定句仍會觸發防禦** | P4、P5 | 結果頁字面出現「不合格」三字(即使是「這不是『不合格』」) |
| **H4 單向透明加深對立** | P5 全程戒心未解 | 信任頁**沒有**任何中途自身處境的揭露 |
| **H5 第三方卡點無工具可用** | P4 卡住 | 流程頁**沒有**說服家人/房東的內容 |
| **H6 心動當下看不到校準** | P3 衝動預約 | 期待校準題藏在 CTA 點擊之後,首屏不可見 |
| **H7 頁面缺主標題** | 全部 | 7 個頁面 H1 為 0(Section 全用 h2) |

### 第一輪優化(R1)

1. **測驗中途回饋** — 走到第 6 題起顯示「依你目前的回答,有 N 位夥伴的作息和你合得來」+「想先看看?答案都會留著」。讓填答者不必走完 12 題才有回報。
2. **90 天頁新增「先說清楚:這不是在盯著你」** — 四點:系統提醒不是人催、只有中途看得到、節奏可自己調或暫停、一句話就夠。
3. **結果頁移除「不合格」字面** — 改為「你沒有被擋下來,也沒有被扣分」。
4. **信任頁新增「我們這邊的實話」** — 四張卡:沒有公權力所以只能靠問、審核是怕重來一次(退養實例)、小團隊回覆可能會慢、**你有拒絕的權利**。
5. **流程頁新增「卡住的通常不是你,是還沒點頭的人」** — 給房東的說明(抓壞牆面/氣味/恢復原狀三個常見疑慮)、給同住家人的說明(分工表、過敏可現場測、三方對談)。
6. **動物詳情頁前置期待校準** — 依動物特性動態生成 3 題,放在「牠的故事」與「一起生活的真實樣貌」之間;慢熟貓問「三個月還不讓你抱你願意嗎」、老貓問「陪你的時間可能不是十五年」、需成對問「預算是以兩隻計算的嗎」,末題固定為「你心動的是牠的故事,還是上面這些每一天都要做的事?」
7. **每頁唯一 H1**(`Section` 新增 `level` 參數)。

## 四、第二輪測試:驗證與新發現

### R1 驗證結果:全數通過
中途回饋出現(實測顯示「有 8 位夥伴的作息和你合得來」)、監視感四點齊備、「不合格」已消失、中途處境四卡到位、房東與家人工具到位、期待校準隨動物而異(拿鐵顯示慢熟提問、雪見顯示餵藥與熟齡壽命)。

### 第二輪新發現(第一輪未觸及的層面)

| 假設 | 發現 |
|---|---|
| **H8 久候動物仍會沉底** | 卡片**沒有**等待天數,探索頁**沒有**排序功能 |
| **H9 支持全靠中途,無法規模化** | 訪談 4 實務中最有效的是「我沒空,**其他認養人都會幫忙回答**」,網站完全沒有同儕互助 |
| **H10 回報是純付出** | 訪談 2 的抽獎券構想未實作,回報缺乏正向回饋 |
| **H11 合約看起來只約束認養人** | 流程頁只寫「簽署認養合約」,未說明它同時保護誰 |
| **H12 測驗作答中畫面無 H1** | R1 只修了有 `Section title` 的頁面 |

### 第二輪優化(R2)

1. **久候動物可見度** — `Animal` 新增 `waitingDays`;等待超過 120 天的卡片顯示「已在中途之家等待 N 天。性格穩定的成貓成犬常因為外型不搶眼而被略過,牠值得被多看一眼」;探索頁新增「等待較久的優先」排序。**刻意不使用倒數或稀缺話術**(訪談 1 明確反對)。
2. **同儕互助** — 90 天頁新增「其他認養人,通常比我們更快回你」,三則真實情境問答(躲沙發底下、幼貓咬手、外出籠哀嚎),並註明「可以只看不說話,也可以隨時退出」。
3. **回報回饋** — 幸福回報頁加入抽獎券機制,明寫「**不回報也不會有任何影響——這是謝謝,不是條件**」,並標示尚未實際開放。
4. **合約雙向性** — 責任交接步驟加註:合約寫明你不得棄養,**也寫明我們的義務**——完整病史、90 天支持、以及任何時候你無法繼續時我們一定接回;核對證件但不留存影本。
5. **修正測驗作答中與結果空狀態的 H1**。

### 最終驗證:12 條路由全部 1 個 H1、R2 五項全通過、R1 五項迴歸未退化、零 JavaScript 錯誤。

## 五、兩輪後的 Persona 意願變化

| Persona | 主要阻力 | 兩輪後的處置 |
|---|---|---|
| **P1** 表單恐懼 | 第 6 題起有中途回饋,可先去看動物且答案保留 | 從「填不完就走」變成「有理由走完」 |
| **P2** 隱私戒心 | 監視感四點 +「你有拒絕的權利」+ 回報僅中途可見 | 疑慮被主動說破,而非等他自己猜 |
| **P3** 期待落差 | 心動當下就看到三題校準,末題直指「故事 vs 日常」 | 保留共感,但共感的是真實的牠 |
| **P4** 家人房東 | 可直接轉傳的說明 + 三方對談 | 從「一個人去說服」變成「有工具、有人陪」 |
| **P5** 對立戒心 | 「我們這邊的實話」揭露中途的無力與界線 | 從被審查者,變成知情的共同承擔者 |

## 六、尚未處理、建議下一輪處理

1. **FB 演算法的結構性阻礙**(訪談 3):「文章裡面有連結超過兩個以上,基本上可能會降到幾乎零」。網站的流量假設有風險,需要「可直接貼進 FB 的圖卡」策略,而不是導流連結。
2. **中途端的工作台**:訪談反覆出現「我沒空」「我哪會記得」。認養人端做得再好,中途端沒有省力工具就跑不動。
3. **回應時間的可兌現性**:目前寫「1–2 個工作天」,已在信任頁補上「小團隊可能會慢」,但仍需與實際人力對齊。
4. **黑名單的法律風險**(訪談 3:發黑名單被揚言提告)。網站已承諾不建立公開羞辱式黑名單,內部風險註記的法遵設計仍待處理。
5. **量測**:本次為情境模擬,非真人測試。建議正式版以第 6 題完成率、測驗完成率、預約轉換率、90 天回報率做實際 A/B 驗證。

## 七、誠實聲明

本報告的 persona 行為與意願變化是**依訪談證據建立的情境模擬**,不是真人可用性測試的結果;文中所有百分比與統計皆未使用,即為避免造成有真實量測的錯覺。網站上的信任數字、捐款流向、幸福回報時間軸同樣全部標註為示意資料。
